## 1. Переход в режим конфигурации

```
Switch# conf t
```

`conf t` — сокращение от `configure terminal`.

Переводит коммутатор из привилегированного режима `Switch#` в режим глобальной конфигурации `Switch(config)#`, где можно изменять настройки устройства.


### Чтобы посмотреть текущую конфигурацию, есть два варианта:

```
Switch(config)# do show running-config
```

Или выйти из режима конфигурации:

```
Switch(config)# end
Switch# show running-config
```

`show run` — сокращённая форма команды `show running-config`, которая показывает текущие настройки устройства в оперативной памяти.

## 2. Переход к интерфейсу VLAN 1

```
Switch(config)# interface Vlan1
```

Эта команда открывает режим конфигурации виртуального интерфейса VLAN 1.

После неё приглашение меняется:

```
Switch(config-if)#
```

Что такое VLAN 1?

VLAN — это виртуальная локальная сеть. На коммутаторе Cisco интерфейс `Vlan1` является SVI (Switched Virtual Interface) — логическим интерфейсом, который может иметь собственный IP-адрес.

Важно различать:

- `interface FastEthernet0/1` — физический порт для подключения устройства.
    
- `interface Vlan1` — логический интерфейс для взаимодействия с соответствующей VLAN.
    

IP-адрес на `Vlan1` обычно используется для управления коммутатором, а не для назначения адресов подключённым компьютерам.

## 4. Просмотр доступных команд

```
Switch(config-if)# ?
```

Символ `?` — встроенная контекстная справка Cisco IOS. Она показывает команды, доступные в текущем режиме.

В твоём случае среди них:

|Команда|Назначение|
|---|---|
|`arp`|Настройка параметров ARP|
|`description`|Добавление описания интерфейса|
|`exit`|Возврат на предыдущий уровень конфигурации|
|`ip`|Настройки IP|
|`no`|Отмена настройки или возврат к значению по умолчанию|
|`shutdown`|Административное отключение интерфейса|
|`standby`|Настройка HSRP для резервирования шлюза|

## 6. Назначение IP-адреса

```
Switch(config-if)# ip address 192.168.0.1 255.255.255.0
```

Ты назначил интерфейсу VLAN 1 следующие параметры:

|Параметр|Значение|
|---|---|
|IP-адрес|`192.168.0.1`|
|Маска подсети|`255.255.255.0`|
|Префикс|`/24`|
|Адрес сети|`192.168.0.0`|
|Диапазон адресов узлов|`192.168.0.1–192.168.0.254`|
|Широковещательный адрес|`192.168.0.255`|

Это означает, что интерфейс коммутатора получает адрес `192.168.0.1` в подсети `192.168.0.0/24`.

Например, если компьютер подключён к этой VLAN и имеет адрес `192.168.0.10/24`, он сможет обращаться к интерфейсу коммутатора по адресу `192.168.0.1`, если VLAN и физическое подключение настроены правильно.

## 7. Включение интерфейса

```
Switch(config-if)# no shutdown
```

Команда снимает административный запрет на работу интерфейса.

Противоположная команда:

```
Switch(config-if)# shutdown
```

отключает интерфейс административно.

Но есть нюанс: `no shutdown` не гарантирует, что SVI сразу станет активным. Обычно для этого VLAN должна существовать и быть активной, а на коммутаторе должен быть хотя бы один работающий порт, относящийся к этой VLAN, в зависимости от модели и платформы.

## 8. Как проверить результат

Выполни:

```
Switch(config-if)# end
Switch# show ip interface brief
```

В выводе найди `Vlan1`. Пример ожидаемого результата:

```
Interface    IP-Address      OK? Method Status  Protocol
Vlan1        192.168.0.1     YES manual up      up
```

Если `Status` или `Protocol` показывают `down`, нужно проверить состояние VLAN и подключённых портов.

Чтобы проверить связь с компьютером:

```
Switch# ping 192.168.0.10
```

Здесь `192.168.0.10` — пример адреса компьютера, который должен находиться в той же подсети.

## 9. Что ещё нужно для удалённого управления?

Назначение IP-адреса — только один из шагов. Для полноценного удалённого управления из другой подсети могут потребоваться:

- настройка шлюза управления на коммутаторе второго уровня через `ip default-gateway`;
    
- создание пользователя;
    
- настройка SSH и VTY-линий;
    
- разрешение доступа соответствующими сетевыми правилами.
    

Главное, что нужно запомнить: `interface Vlan1` выбирает логический интерфейс, `ip address` назначает ему адрес, а `no shutdown` разрешает его работу. Эти команды сами по себе не включают SSH и не гарантируют удалённый доступ.
