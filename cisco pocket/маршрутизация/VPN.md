##### vpn - шифрованный канал между маршрутизаторами. Site-to-Site IPsec VPN между двумя маршрутизаторами Cisco

# Инструкция по настройке Site-to-Site IPsec VPN на маршрутизаторах Cisco

## 1. Цель

Настроить защищённое VPN-соединение между двумя офисами с использованием технологии Site-to-Site IPsec VPN.

VPN позволяет передавать данные между локальными сетями через общедоступную сеть (Internet), обеспечивая шифрование и проверку целостности передаваемой информации.

В результате настройки компьютеры из локальной сети первого офиса смогут безопасно взаимодействовать с устройствами второго офиса.

## 2. Схема сети

Используется следующая схема:

|Параметр|Офис 1 (Router1)|Офис 2 (Router2)|
|---|---|---|
|Локальная сеть|192.168.1.0/24|192.168.2.0/24|
|Шлюз локальной сети|192.168.1.1|192.168.2.1|
|WAN IP|212.212.10.2|212.212.20.2|
|WAN-шлюз|По схеме провайдера|212.212.20.1|
|VPN Peer|212.212.20.2|212.212.10.2|

**Важно:** в этой лабораторной схеме WAN-адреса представлены как адреса внешних интерфейсов маршрутизаторов. В реальной сети они должны быть доступны друг другу через Интернет.

## 3. Принцип работы IPsec VPN

Настройка IPsec VPN состоит из двух основных этапов:

**IKE Phase 1 — создание защищённого канала управления.**

Маршрутизаторы согласовывают параметры безопасности и проверяют подлинность друг друга. Для аутентификации в нашей конфигурации используется предварительно согласованный ключ (Pre-Shared Key).

**IKE Phase 2 — создание IPsec SA.**

Маршрутизаторы согласовывают параметры шифрования и целостности данных, после чего создают защищённый канал для передачи пользовательского трафика.

Для работы VPN используются следующие параметры:

- Шифрование: 3DES.
    
- Хеширование: MD5.
    
- Аутентификация: Pre-Shared Key.
    
- Diffie-Hellman Group: 2.
    
- IPsec Transform Set: ESP-3DES, ESP-MD5-HMAC.
    

_Примечание: это параметры учебной конфигурации. Для реальных развёртываний следует использовать современные алгоритмы, например AES и SHA-256, а также более стойкие группы Diffie-Hellman._

## 4. Предварительная настройка интерфейсов

Перед настройкой VPN необходимо убедиться, что маршрутизаторы имеют корректные IP-адреса и могут взаимодействовать через внешнюю сеть.

### Router1

```
enable
configure terminal

interface GigabitEthernet0/0/0
 description WAN
 ip address 212.212.10.2 255.255.255.0
 ip nat outside
 no shutdown
exit

interface GigabitEthernet0/0/1
 description LAN
 ip address 192.168.1.1 255.255.255.0
 ip nat inside
 no shutdown
exit
```

### Router2

```
enable
configure terminal

interface GigabitEthernet0/0/0
 description WAN
 ip address 212.212.20.2 255.255.255.0
 ip nat outside
 no shutdown
exit

interface GigabitEthernet0/0/1
 description LAN
 ip address 192.168.2.1 255.255.255.0
 ip nat inside
 no shutdown
exit
```

Назначение интерфейсов:

- WAN — интерфейс, подключённый к внешней сети.
    
- LAN — интерфейс, подключённый к локальной сети офиса.
    
- `ip nat inside` и `ip nat outside` обозначают внутреннюю и внешнюю стороны для механизма NAT.
    

Проверить состояние интерфейсов:

```
show ip interface brief
```

## 5. Настройка маршрутизации

Маршрутизаторы должны знать, куда направлять пакеты, предназначенные для внешней сети.

В нашем примере используется маршрут по умолчанию.

### Router1

```
ip route 0.0.0.0 0.0.0.0 212.212.10.1
```

### Router2

```
ip route 0.0.0.0 0.0.0.0 212.212.20.1
```

Маршрут по умолчанию направляет неизвестный трафик через внешний шлюз.

Также необходимо убедиться, что маршрутизаторы имеют IP-связность друг с другом по WAN-адресам.

Например, с Router2:

```
ping 212.212.10.2
```

Без доступности внешнего VPN Peer установить IPsec-соединение не получится.

## 6. Настройка IKE Phase 1

На обоих маршрутизаторах необходимо создать одинаковую политику IKE.

### Router1 и Router2

```
crypto isakmp policy 1
 encr 3des
 hash md5
 authentication pre-share
 group 2
exit
```

Пояснение команд:

|Команда|Назначение|
|---|---|
|`crypto isakmp policy 1`|Создание политики IKE|
|`encr 3des`|Алгоритм шифрования|
|`hash md5`|Алгоритм проверки целостности|
|`authentication pre-share`|Аутентификация с помощью общего ключа|
|`group 2`|Группа Diffie-Hellman|

### Настройка предварительно согласованного ключа

На Router1 указывается внешний IP-адрес Router2:

```
crypto isakmp key cisco address 212.212.20.2
```

На Router2 указывается внешний IP-адрес Router1:

```
crypto isakmp key cisco address 212.212.10.2
```

Ключ `cisco` должен совпадать на обоих маршрутизаторах.

## 7. Настройка IPsec Phase 2

На этом этапе создаётся Transform Set — набор параметров защиты пользовательского трафика.

На обоих маршрутизаторах:

```
crypto ipsec transform-set TS esp-3des esp-md5-hmac
```

Пояснение:

- `TS` — имя Transform Set.
- `esp-3des` — шифрование передаваемых данных.
- `esp-md5-hmac` — проверка целостности и подлинности данных.

## 8. Создание ACL для VPN-трафика

Необходимо определить, какой именно трафик должен проходить через VPN.

Для этого создаётся расширенный ACL.

### Router1

```
ip access-list extended FOR-VPN
 permit ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255
exit
```

### Router2

```
ip access-list extended FOR-VPN
 permit ip 192.168.2.0 0.0.0.255 192.168.1.0 0.0.0.255
exit
```

Данные правила являются зеркальными.

ACL определяет так называемый _Interesting Traffic_ — трафик, который должен быть защищён IPsec.

Например:

- Источник: `192.168.1.10`.
    
- Назначение: `192.168.2.10`.
    

Такой трафик соответствует ACL и будет передаваться через VPN.

Важно: этот ACL не является обычным фильтром доступа на интерфейсе. Его не нужно привязывать командой `ip access-group`. Он будет использоваться внутри Crypto Map.

## 9. Создание Crypto Map

Crypto Map объединяет основные параметры VPN:

- IP-адрес удалённого VPN Peer.
    
- Transform Set.
    
- ACL, определяющий защищаемый трафик.
    

### Router1

```
crypto map CMAP 10 ipsec-isakmp
 set peer 212.212.20.2
 set transform-set TS
 match address FOR-VPN
exit
```

### Router2

```
crypto map CMAP 10 ipsec-isakmp
 set peer 212.212.10.2
 set transform-set TS
 match address FOR-VPN
exit
```

Пояснение:

|Команда|Назначение|
|---|---|
|`crypto map CMAP 10 ipsec-isakmp`|Создание Crypto Map|
|`set peer`|Указание внешнего IP-адреса удалённого маршрутизатора|
|`set transform-set TS`|Выбор параметров шифрования|
|`match address FOR-VPN`|Выбор ACL с защищаемым трафиком|

## 10. Привязка Crypto Map к WAN-интерфейсу

Созданную Crypto Map необходимо применить к внешнему интерфейсу маршрутизатора.

### Router1

```
interface GigabitEthernet0/0/0
 crypto map CMAP
exit
```

### Router2

```
interface GigabitEthernet0/0/0
 crypto map CMAP
exit
```

Это важный этап настройки.

Crypto Map не является физическим или виртуальным интерфейсом. Это набор параметров IPsec, который применяется к интерфейсу, через который маршрутизатор взаимодействует с удалённым VPN Peer.

## 11. Исключение VPN-трафика из NAT (NAT Exemption)

Если на маршрутизаторах используется NAT Overload (PAT), необходимо исключить межофисный трафик из трансляции адресов.

Причина: IPsec должен видеть исходные адреса локальных сетей, чтобы трафик соответствовал ACL `FOR-VPN`.

### Router1

```
ip access-list extended NAT-ACL
 deny ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255
 permit ip 192.168.1.0 0.0.0.255 any
exit

ip nat inside source list NAT-ACL interface GigabitEthernet0/0/0 overload
```

### Router2

```
ip access-list extended NAT-ACL
 deny ip 192.168.2.0 0.0.0.255 192.168.1.0 0.0.0.255
 permit ip 192.168.2.0 0.0.0.255 any
exit

ip nat inside source list NAT-ACL interface GigabitEthernet0/0/0 overload
```

Пояснение:

- `deny` — не выполнять NAT для межофисного трафика.
    
- `permit` — разрешить NAT для остального трафика локальной сети, например при выходе в Интернет.
    
- `overload` — использовать PAT, позволяющий нескольким устройствам выходить в Интернет через один внешний IP-адрес.
    

Важно: ACL `NAT-ACL` используется именно в правиле NAT. Не нужно привязывать её к физическому интерфейсу через `ip access-group`.

Если NAT в вашей сети не настроен, этот раздел не требуется. Если ранее уже существовало правило NAT Overload, его нужно корректно заменить или изменить, чтобы не оставить два конфликтующих правила.

## 12. Проверка VPN-соединения

После завершения настройки необходимо проверить работу VPN.

### 12.1. Проверка параметров Crypto Map

```
show crypto map
```

Команда позволяет проверить:

- Указан ли правильный VPN Peer.
    
- Выбран ли правильный Transform Set.
    
- Привязан ли нужный ACL.
    

### 12.2. Проверка ACL

```
show access-lists
```

Проверяем, что ACL `FOR-VPN` содержит правильные локальную и удалённую подсети.

### 12.3. Проверка IKE Phase 1

```
show crypto isakmp sa
```

При успешном согласовании IKEv1 обычно отображается состояние:

```
QM_IDLE
```

Это означает, что IKE-согласование завершено и SA находится в рабочем состоянии.

### 12.4. Проверка IPsec Phase 2

```
show crypto ipsec sa
```

Особое внимание необходимо уделить счётчикам:

- `#pkts encaps` — количество пакетов, которые были обработаны и инкапсулированы для отправки через IPsec.
    
- `#pkts decaps` — количество пакетов, которые были приняты и расшифрованы.
    

При передаче трафика значения счётчиков должны увеличиваться.

### 12.5. Проверка NAT

```
show ip nat translations
show ip nat statistics
```

Эти команды позволяют проверить таблицу трансляций и статистику NAT.

Межофисный трафик не должен подвергаться трансляции адресов.

## 13. Тестирование передачи данных

Для проверки работы VPN необходимо отправить ICMP-запросы между устройствами двух офисов.

Например:

Из офиса 1:

```
ping 192.168.2.10
```

Из офиса 2:

```
ping 192.168.1.10
```

Для корректного тестирования компьютеры должны иметь правильные IP-адреса и шлюзы по умолчанию.

Первый ping может завершиться неудачно, пока маршрутизаторы устанавливают IKE/IPsec SA. Следующие запросы должны проходить после успешного согласования.

После тестирования необходимо повторно выполнить:

```
show crypto isakmp sa
show crypto ipsec sa
```

И убедиться, что счётчики `encaps` и `decaps` увеличиваются.

## 14. Как проходит пакет через VPN

Рассмотрим пример:

Компьютер первого офиса `192.168.1.10` отправляет пакет серверу `192.168.2.10`.

1. Компьютер отправляет пакет на свой шлюз `192.168.1.1`.
    
2. Router1 получает пакет и проверяет таблицу маршрутизации.
    
3. Пакет направляется через WAN-интерфейс.
    
4. Crypto Map проверяет пакет по ACL `FOR-VPN`.
    
5. Поскольку адрес назначения относится к удалённой локальной сети, пакет соответствует ACL.
    
6. Если VPN ещё не установлен, маршрутизаторы выполняют IKE Phase 1 и Phase 2.
    
7. Router1 шифрует исходный пакет с помощью IPsec ESP.
    
8. Зашифрованный пакет отправляется через внешнюю сеть к WAN-адресу Router2.
    
9. Router2 получает пакет, проверяет его и расшифровывает.
    
10. После расшифровки Router2 получает исходный пакет с адресами `192.168.1.10` и `192.168.2.10`.
    
11. Router2 направляет пакет в локальную сеть офиса 2.
    
12. Сервер получает ICMP-запрос и отправляет ответ обратно через VPN.
    

Таким образом, по внешней сети передаются зашифрованные данные, а исходные IP-адреса локальных устройств сохраняются внутри IPsec-туннеля.

## 15. Типовые проблемы при настройке

|Проблема|Возможная причина|
|---|---|
|VPN не устанавливается|Неверный IP-адрес Peer|
|IKE SA не создаётся|Различаются PSK или параметры IKE|
|Phase 1 работает, но Phase 2 нет|Не совпадают Transform Set или ACL|
|Ping между офисами не проходит|Неверная маршрутизация или шлюз|
|Счётчик encaps увеличивается, decaps нет|Удалённая сторона не принимает или не обрабатывает пакеты|
|Межофисный трафик не работает при включённом NAT|Не настроено исключение VPN-трафика из NAT|
|VPN не активируется|Crypto Map не привязана к WAN-интерфейсу|

## 16. Итог

Для настройки Site-to-Site IPsec VPN необходимо выполнить следующие действия:

1. Настроить WAN- и LAN-интерфейсы маршрутизаторов.
    
2. Проверить IP-связность между внешними адресами маршрутизаторов.
    
3. Настроить маршрутизацию.
    
4. Создать IKE Policy (Phase 1).
    
5. Указать Pre-Shared Key для удалённого VPN Peer.
    
6. Создать IPsec Transform Set (Phase 2).
    
7. Создать зеркальные ACL для определения защищаемого трафика.
    
8. Создать Crypto Map и указать в ней Peer, Transform Set и ACL.
    
9. Привязать Crypto Map к внешнему WAN-интерфейсу.
    
10. При использовании NAT настроить исключение межофисного трафика из трансляции.
    
11. Проверить состояние VPN и протестировать передачу данных.
    

**Результат:** два офиса получают возможность безопасно обмениваться данными через общедоступную сеть с использованием IPsec VPN.
